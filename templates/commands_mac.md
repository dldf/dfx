## Workflow

The recommended process is to begin by converting a PDF document to markdown text, and visually compare the PNG renderings of the new revised pages against the original PDF pages. If needed, manually edit the content.md to fix any conversion mistakes, and then check the edited markdown to make sure it is acceptable.

Conversion commands do not overwrite existing document folders. Preview commands rebuild PNGs and HTML from your edited Markdown. The commands below are single lines, even if your viewer wraps them.

_See the **Command Usage Instructions** below for how to issue commands._

## Optional: discover PDFs on a website

$scan_intro

```sh
$scan_command
python site.py tree
python site.py download
```

These commands:

1. Follow links within the website folder to discover PDFs, then offer to download them. Add `--scan-only` to skip the download prompt, or `--max-urls 100` to limit the scan to 100 visited URLs.
2. Display discovered PDFs and their local workflow status in a tree diagram.
3. Ask for confirmation before downloading PDFs into the local `1_downloads/` folder. This step is unnecessary if you already downloaded them during the scan.

The scan visits up to **250 URLs by default**, including pages and PDFs. Increase `--max-urls` to search further. It follows the website’s automated-access rules in `robots.txt` and may miss unlinked files or links generated by JavaScript, so it cannot guarantee finding every PDF.

### List PDF folders without saving a scan

```sh
$scan_command --folders --max-urls 100
```

This lists only folders containing PDFs found during this scan, with a count for
each folder. Each unique PDF URL counts once in its immediate folder, not in
parent folders. It does not print individual PDF URLs or a status tree, save or
change `inventory.json`, or offer downloads. It works without an inventory file.
The scan still follows links; limits, excluded folders, and inaccessible pages can
make the listing incomplete. Run a normal scan later to save results for downloading.

### Exclude website folders

Create `.pdfignore` in the `pdf2md` project root. Replace these example URLs with
full URLs of folders to skip:

```text
# Skip these folders and everything beneath them
https://example.edu/department/archive/
https://example.edu/department/old-reports/
```

Blank lines and lines beginning with `#` are ignored. Each entry is a literal
folder URL; wildcards, query strings, and fragments are not supported. A trailing
slash is optional. `/archive/` excludes that folder and its descendants, but not
`/archive-old/`. Rules apply to the specified scheme and host.

Exclusions apply to normal scans, folder summaries, downloads, and redirects.
Previously saved records and downloaded files are kept; excluded records can
still appear in `site.py tree`, but are not offered for download. Excluding the
scan root stops the scan with an error. If `.pdfignore` is absent, nothing is
excluded beyond the existing scope and `robots.txt` rules.

## Tracking multiple conversions in a project

$tracking_table

The tree tracks file presence automatically: **[1] Downloaded** in `1_downloads/`, **[2] Pending Review** in `2_pending_review/`, and **[3] Ready to Publish** in `3_ready_to_publish/`. The highest stage present wins. Discovered URLs without local files are unnumbered and marked “not downloaded.” Custom output locations are outside this tracked workflow.

For documents in `2_pending_review/`, run the verification command after human review. It prompts for your name and records the date/time. Markdown, HTML, and assets are copied and checked before originals are removed; HTML becomes `frompdf.html` without being rebuilt. The entire `review/` folder, including handwritten notes, is deleted after success. A two-line `ready_to_publish.txt` receipt stays in the pending document folder with your review record and a link to the ready folder. Existing destinations are never overwritten. Refresh the preview before verification if you edited the Markdown.

## Command Usage Instructions 📓

**Copy/Paste** the commands **from** the examples and tables above **into** your terminal (at the pdf2md root). Open a new Terminal Window to get the command line interface, then:

### Example

Copy a command like `python convert.py --help`\
Paste it into a terminal at the **pdf2md** prompt. Copy only the command, not the prompt:

```
(.venv) yourcomputer pdf2md % python convert.py --help
```

These commands work in macOS Terminal with zsh or bash. They also work in bash or zsh on Linux and other Unix-like systems when the project dependencies are installed. Browser installation paths and automatic detection can differ by OS.

Open your terminal in the `pdf2md` project root. Paths in the commands are relative to that root. The source PDFs and output folders must be present in the same project layout.

## Environment Setup (a one-time process) ⚙️

Run these from the project root:

| Step | macOS / Linux — bash or zsh | Windows — PowerShell |
| --- | --- | --- |
| Create the environment | `python3 -m venv .venv` | `py -m venv .venv` |
| Activate it | `source .venv/bin/activate` | `.\.venv\Scripts\Activate.ps1` |
| Install dependencies | `python -m pip install -r requirements.txt` | `python -m pip install -r requirements.txt` |

If you have newly downloaded the project (as from github.com), and are preparing to work locally, the first step is to configure the Python virtual environment. These steps create the `.venv` folder your system needs to carry out the commands in the pdf2md project.

Activate the Python virtual environment with `source .venv/bin/activate` to make your terminal use the right Python installation and packages.

```
yourcomputer pdf2md % source .venv/bin/activate
```

When the environment is active, you'll see the `(.venv)` at the start of the prompt:

```
(.venv) yourcomputer pdf2md %
```

Activation is optional: replace `python` with `.venv/bin/python` in any command. In a POSIX shell without `source`, use `. .venv/bin/activate` instead. Recreate the virtual environment when moving between operating systems. Pandoc and Chrome must also be installed.
