# macOS
### Example commands

These examples use `document.pdf`. Replace it with your PDF filename and use
the matching document folder for review and staging. Run commands from the
project root, even though this guide is in `docs/`.

```
source .venv/bin/activate
```
Activate the Environment (if needed). Run from the project root in each new terminal session to activate the Python virtual environment. _See **Environment Setup** instructions below for getting started._

## Generate Markdown ✏️

```
dfx convert "1_downloads/document.pdf"
```
Converts the example PDF into `2_pending_review/document/`. Run from the project root. Existing document folders are never overwritten.\
After success, the terminal prints the review command for copying and pasting; it does not run it automatically.

To convert all PDFs in the input directory, use:

```
dfx convert "1_downloads"
```

## Rebuild Preview 🔍

```
dfx review "2_pending_review/document" --inspect
```
Creates PNG and HTML previews from the document folder. Run this from the project root after editing the MD to see new PNGs and index.html; leaves MD unchanged. Styling is linked from assets/main.css. (`--inspect` at the end is optional; it opens the new HTML in your browser.)

The source PDF is found from the matching path under `1_downloads/`, then by filename under `2_pending_review/`, using the recorded hash when available. If it cannot be identified, enter its path at the prompt, or press Enter on a blank line or Ctrl+C to cancel before any files change.

After successful review, the terminal prints the stage command for copying and pasting; it does not run it automatically.

## Stage for Publication 🚀

```
dfx stage "2_pending_review/document"
```

After the conversion has been reviewed and edited (if necessary) by a human, it is ready to be published. This command moves the new files to a publication folder. From there they may be uploaded to a web server.

## Workflow

The recommended process is to begin by converting a PDF document to markdown text, and visually compare the PNG renderings of the new revised pages against the original PDF pages. If needed, manually edit the content.md to fix any conversion mistakes, and then check the edited markdown to make sure it is acceptable.

Conversion commands do not overwrite existing document folders. Preview commands rebuild PNGs and HTML from your edited Markdown. The commands below are single lines, even if your viewer wraps them.

_See the **Command Usage Instructions** below for how to issue commands._

## Optional: discover PDFs on a website

Replace `https://example.edu/department/` with the website folder you want to search. This is an example URL, not a required source for your PDF.

```sh
dfx site scan "https://example.edu/department/"
dfx site tree
dfx site download
```

These commands:

1. Follow links within the website folder to discover PDFs, then offer to download them. Add `--scan-only` to skip the download prompt, or `--max-urls 100` to limit the scan to 100 visited URLs.
2. Display discovered PDFs and their local workflow status in a tree diagram.
3. Ask for confirmation before downloading PDFs into the local `1_downloads/` folder. This step is unnecessary if you already downloaded them during the scan.

The scan visits up to **250 URLs by default**, including pages and PDFs. Increase `--max-urls` to search further. It follows the website’s automated-access rules in `robots.txt` and may miss unlinked files or links generated by JavaScript, so it cannot guarantee finding every PDF.

### List PDF folders without saving a scan

```sh
dfx site scan "https://example.edu/department/" --folders --max-urls 100
```

This lists only folders containing PDFs found during this scan, with a count for
each folder. Each unique PDF URL counts once in its immediate folder, not in
parent folders. It does not print individual PDF URLs or a status tree, save or
change `inventory.json`, or offer downloads. It works without an inventory file.
The scan still follows links; limits, excluded folders, and inaccessible pages can
make the listing incomplete. Run a normal scan later to save results for downloading.

### Exclude website folders

Create `.pdfignore` in the `dfx` project root. Replace these example URLs with
full URLs of folders to skip:

```text
# Skip these folders and everything beneath them
https://example.edu/department/archive/
https://example.edu/department/old-reports/
```

Blank lines and lines beginning with `#` are ignored. Each entry is a literal
folder URL; wildcards, query strings, and fragments are not supported. A trailing
slash is optional. `/archive/` excludes that folder and its descendants, but not
`/archive-old/`. Rules apply to the specified scheme and host.

Exclusions apply to normal scans, folder summaries, downloads, and redirects.
Previously saved records and downloaded files are kept; excluded records can
still appear in `dfx site tree`, but are not offered for download. Excluding the
scan root stops the scan with an error. If `.pdfignore` is absent, nothing is
excluded beyond the existing scope and `robots.txt` rules.

## Tracking multiple conversions in a project

| Purpose | Command | Notes |
| --- | --- | --- |
| Show latest scan’s status tree | `dfx site tree` | Shows workflow status based on local files. |
| Show this scope’s status tree | `dfx site tree "https://example.edu/department/"` | Shows this website folder. |
| Mark reviewed and prepare for publication | `dfx stage "2_pending_review/document"` | Prompts for your name, stages index.html and assets in 3_ready_to_publish/, archives Markdown and log in assets/_pdf2md/, and removes review/. Leaves a dated receipt. Does not rebuild HTML. |
| Show conversion help | `dfx convert --help` | Lists conversion options. |
| Show review help | `dfx review --help` | Lists review options. |
| Show website command help | `dfx site --help` | Lists website commands. |
| Show scan options | `dfx site scan --help` | Lists scan options. |
| Show verification help | `dfx stage --help` | Lists verification options. Custom output locations are outside the tracked workflow. |
| Run regression tests | `python -m unittest discover -s tests -q` | Checks converter and preview behavior. |

The tree tracks file presence automatically: **[1] Downloaded** in `1_downloads/`, **[2] Pending Review** in `2_pending_review/`, and **[3] Ready to Publish** in `3_ready_to_publish/`. New ready documents require `index.html`, `assets/main.css`, and both archived Markdown files. Legacy root-level Markdown remains recognized. The highest stage present wins. Discovered URLs without local files are unnumbered and marked “not downloaded.” Custom output locations are outside this tracked workflow.

For documents in `2_pending_review/`, run the verification command after human review. It prompts for your name and records the date/time. HTML and assets are copied and checked before originals are removed. The staged folder contains only `index.html` and `assets/`; `content.md` and `review/log.md` are archived in `assets/_pdf2md/` with relative links updated. HTML is not rebuilt. The remaining `review/` files are deleted after success. A two-line `ready_to_publish.txt` receipt stays in the pending document folder with your review record and a link to the ready folder. Existing destinations are never overwritten. Refresh the preview before verification if you edited the Markdown.

## Command Usage Instructions 📓

**Copy/Paste** the commands **from** the examples and tables above **into** your terminal (at the dfx root). Open a new Terminal Window to get the command line interface, then:

### Example

Copy a command like `dfx convert --help`\
Paste it into a terminal at the **dfx** prompt. Copy only the command, not the prompt:

```
(.venv) yourcomputer dfx % dfx convert --help
```

These commands work in macOS Terminal with zsh or bash. They also work in bash or zsh on Linux and other Unix-like systems when the project dependencies are installed. Browser installation paths and automatic detection can differ by OS.

Open your terminal in the `dfx` project root. Paths in the commands are relative to that root. The source PDFs and output folders must be present in the same project layout.

## Environment Setup (a one-time process) ⚙️

Run these from the project root:

| Step | macOS / Linux — bash or zsh | Windows — PowerShell |
| --- | --- | --- |
| Create the environment | `python3 -m venv .venv` | `py -m venv .venv` |
| Activate it | `source .venv/bin/activate` | `.\.venv\Scripts\Activate.ps1` |
| Install project and dependencies | `python -m pip install -e .` | `python -m pip install -e .` |

If you have newly downloaded the project (as from github.com), and are preparing to work locally, the first step is to configure the Python virtual environment. These steps create the `.venv` folder your system needs to carry out the commands in the dfx project.

Activate the Python virtual environment with `source .venv/bin/activate` to make your terminal use the right Python installation and packages.

```
yourcomputer dfx % source .venv/bin/activate
```

When the environment is active, you'll see the `(.venv)` at the start of the prompt:

```
(.venv) yourcomputer dfx %
```

Activation is optional: replace `dfx` with `.venv/bin/dfx`, or `python` with `.venv/bin/python`. In a POSIX shell without `source`, use `. .venv/bin/activate` instead. Recreate the virtual environment when moving between operating systems. Pandoc and Chrome must also be installed.
